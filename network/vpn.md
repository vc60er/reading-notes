## VPN 原理：从网络隧道到加密通信

### VPN 的本质

- 通过 UDP 承载的虚拟网络链路，将不同主机上的虚拟网络接口连接起来，从而使两个独立的网络协议栈能够交换 IP 数据包。

- vpn 的本质是，通过 udp 串联起来的虚拟网络接口实现的网络。虚拟网络接口的下层协议是一个 udp 通道，而不是网络通道

- 因为，增加虚拟网络接口，对系统层来说加入了一个新的局域网，对应用层来说可以无感知的访问这个局域网

## 虚拟网络接口的原理（Linux）

### 核心原理

虚拟网络接口，就是通过软件模拟出来的网络接口。它和物理网卡一样，可以参与 IP 地址配置、路由选择、数据包收发，但不需要真实的网卡硬件。



管理物理和虚拟网络接口两者最大的区别是数据包最终交给谁处理：

- 物理网卡：数据包最终交给网卡驱动，通过硬件发送。
- 虚拟网卡：数据包交给软件处理，可以转发给其他虚拟设备、用户态程序，或者封装后通过物理网络传输。



因此，虚拟网卡的核心价值是：让软件能够像真实网卡一样接收、发送和处理网络数据包。



## TUN 和 TAP 的实现

在 VPN 场景中，最常见的是 TUN/TAP 虚拟网络设备。

|              | TUN          | TAP              |
| ------------ | ------------ | ---------------- |
| 模拟对象     | 三层网络接口 | 二层以太网接口   |
| 收发数据     | IP 包        | 以太网帧         |
| 包含以太网头 | 否           | 是               |
| 典型用途     | VPN、IP 隧道 | 虚拟机、二层桥接 |

以 TUN 为例：

```
          Linux 内核                  用户态
       ────────────────            ──────────────

           IP 协议层
               │
               ▼
           路由选择
               │
               ▼
         ┌───────────┐
         │ TUN 驱动  │
         └─────┬─────┘
               │
               │  /dev/net/tun
               │
               ▼
         ┌───────────┐
         │ VPN 进程  │
         └───────────┘
```

这里有两个核心机制：

1. 内核 → 用户态

当内核路由选择 `tun0` 时，IP 包进入 TUN 驱动。

VPN 程序通过读取 TUN 对应的文件描述符获取数据包，例如调用 `read()`。

2. 用户态 → 内核

VPN 程序收到远程数据并完成解封装后，通过 `write()` 将 IP 包写入 TUN。

TUN 驱动将其作为网络设备收到的数据包，交回内核 IP 接收路径处理。

所以，TUN 实际上提供了一条内核网络协议栈与用户态程序之间传递 IP 包的通道。



### 虚拟网卡是如何创建的？

Linux 的 TUN/TAP 驱动提供 `/dev/net/tun` 设备文件。

用户态程序主要完成三件事：

1. `open("/dev/net/tun")`：打开 TUN/TAP 驱动。
2. `ioctl(TUNSETIFF)`：创建或连接虚拟网络接口，指定 TUN/TAP 类型。
3. `read()/write()`：与内核交换数据包。

创建后，系统会出现 `tun0` 这样的网络接口，可以通过 `ip addr` 配置地址，通过 `ip route` 配置路由。



```c
// 1. 创建 TUN
int fd = open("/dev/net/tun", O_RDWR);

struct ifreq ifr = {0};
ifr.ifr_flags = IFF_TUN | IFF_NO_PI;
strcpy(ifr.ifr_name, "tun0");

ioctl(fd, TUNSETIFF, &ifr);

/**
这里：
- IFF_TUN：创建三层虚拟网卡，读取的是 IP 包。
- IFF_NO_PI：不包含额外的 TUN Packet Information 头。
- TUNSETIFF：向 TUN 驱动申请创建或绑定接口。
- fd：用于后续读写虚拟网卡。
*/

// 2. 读取 IP 包
unsigned char buf[65535];
ssize_t n = read(fd, buf, sizeof(buf));

// 3. 写入 IP 包
ssize_t n = write(fd, buf, packet_len);
```





### 虚拟网卡不只有 TUN/TAP

| 类型   | 核心机制                                   | 典型用途         |
| ------ | ------------------------------------------ | ---------------- |
| TUN    | 将 IP 包交给用户态程序                     | VPN              |
| TAP    | 将以太网帧交给用户态程序                   | 二层虚拟网络     |
| veth   | 两个接口成对连接，一端发送、另一端接收     | Docker、容器网络 |
| bridge | 在多个网络接口之间按 MAC 地址转发帧        | 容器、虚拟机互联 |
| VLAN   | 为以太网帧增加 VLAN 标识，实现逻辑网络隔离 | 网络隔离         |

它们共享 Linux 网络设备抽象，但虚拟设备的转发机制并不相同。例如，veth 可以在内核内部传递数据包，不需要用户态进程读取和写入。



### 总结

理解虚拟网络接口，抓住三个核心机制即可：

- 统一接口：Linux 将物理网卡和虚拟网卡都抽象为网络设备，因此它们都能参与网络协议栈的数据收发。
- 软件收发：虚拟网卡没有专属物理传输介质，而是通过软件完成数据包的传递。
- 可编程转发：软件可以决定如何处理收到的数据包，比如转发给容器、交给 VPN 程序或者经其他网络设备发送。
