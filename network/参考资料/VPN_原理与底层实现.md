# VPN 原理：从网络隧道到加密通信

## 一、VPN 的本质

VPN（Virtual Private Network，虚拟专用网络）是一种在公共网络上建立逻辑专用网络的技术。

**核心原理：通过隧道封装、加密认证和路由控制，使原本无法直接安全通信的两个网络节点，能够通过公共网络建立受保护的逻辑连接。**

| 核心机制 | 解决的问题 | 实现方式 |
|---|---|---|
| 隧道封装 | 如何通过公网传输内部网络的数据包 | IP-in-IP、UDP 封装 |
| 加密与认证 | 如何防止窃听、篡改和伪造 | TLS、IPsec、WireGuard |
| 路由控制 | 哪些流量进入 VPN | 路由表、策略路由 |
| 虚拟网络接口 | 如何与操作系统网络栈集成 | TUN、TAP |

VPN 不等于加密代理。VPN 通常在网络层或链路层构建逻辑网络，而 HTTP/SOCKS 代理主要在应用层转发连接。

## 二、VPN 的整体架构

以远程接入 VPN 为例：

```text
客户端（业务应用 / TCP-IP）                    VPN 服务器
      |                                           |
  TUN + VPN 加密  ===== 公共互联网 =====>    VPN 解密 + TUN
                                                  |
                                             企业内网 / 网站
```

假设：

- 客户端公网地址：`1.1.1.1`
- VPN 服务器公网地址：`2.2.2.2`
- 客户端 VPN 地址：`10.8.0.2`
- VPN 服务器虚拟地址：`10.8.0.1`
- 企业内网目标服务器：`192.168.1.100`

**外层网络**使用公网地址，将加密数据送到 VPN 服务器；**内层网络**使用虚拟网络地址与目标地址，表达真正想访问的目标。两层地址空间彼此独立。

## 三、VPN 隧道是如何实现的？

### 3.1 原始 IP 数据包

```text
┌───────────────────────────────────┐
│ IP Header                         │
│ Source: 10.8.0.2                  │
│ Dest:   192.168.1.100             │
├───────────────────────────────────┤
│ TCP Header                        │
├───────────────────────────────────┤
│ Application Data                  │
└───────────────────────────────────┘
```

公网路由器通常不会为私有目标地址 `192.168.1.100` 提供公网路由。

### 3.2 隧道封装

以 UDP 承载的 VPN 为例：

```text
┌─────────────────────────────────────┐
│ Outer IP Header                     │
│ Source: 1.1.1.1                     │
│ Dest:   2.2.2.2                     │
├─────────────────────────────────────┤
│ UDP Header + VPN Protocol Header    │
├─────────────────────────────────────┤
│ Encrypted & Authenticated Payload   │
│  ┌───────────────────────────────┐  │
│  │ Inner IP Header               │  │
│  │ 10.8.0.2 → 192.168.1.100      │  │
│  │ TCP Header + App Data         │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

以上为概念示意，实际协议可能有 Nonce、认证标签等字段。

公网只负责把外层数据包送到 `2.2.2.2`。服务器接收并验证、解密后，还原内部 IP 包，再按照内网路由转发。响应通过隧道反向传递。

**VPN 隧道不是独立的物理线路，而是在既有网络上封装和传输另一套网络的数据包。**

## 四、操作系统如何把流量交给 VPN？

### 4.1 TUN / TAP 虚拟网卡

| 特性 | TUN | TAP |
|---|---|---|
| 工作层次 | L3 网络层 | L2 数据链路层 |
| 数据单位 | IP 数据包 | 以太网帧 |
| MAC 地址 | 不包含以太网头 | 包含以太网头 |
| 常见用途 | IP 路由型 VPN | 二层桥接 |

典型 Linux 用户态 TUN VPN 的数据路径：

```text
业务应用 send()/recv()
         ↕
Linux TCP/IP 协议栈（路由选择）
         ↕
TUN 虚拟网络设备
         ↕
VPN 用户态进程（读取、加密、封装；接收、解密、写回）
         ↕
UDP Socket → 物理网卡 → 公网
```

WireGuard 等内核态 VPN 的实现路径可能不同。

用户态 VPN 通常：创建 TUN、配置地址和路由，从 TUN 读取 IP 包并封装加密发送；收到远端数据后解密，写入 TUN，供内核处理。

### 4.2 路由控制

```text
Destination       Gateway      Interface
192.168.1.0/24    10.8.0.1     tun0
default           192.0.2.1    eth0
```

访问 `192.168.1.100` 时，由更具体的路由引导到 `tun0`，其他流量经 `eth0`：这叫 **Split Tunnel（分流隧道）**。

如果默认路由也经 VPN，则大部分流量可进入隧道：这叫 **Full Tunnel（全隧道）**。需要为 VPN 服务器公网地址保留可达路径，避免路由循环；IPv6、DNS 也应单独处理。

## 五、VPN 如何保证安全？

### 5.1 握手与密钥协商

客户端和服务器进行身份验证、密码协商和密钥交换。以 WireGuard 为例：

- Curve25519 密钥协商。
- ChaCha20-Poly1305 认证加密。
- 基于 Noise 的握手协议。
- 定期更新会话密钥，提供前向保密能力。

双方通过密钥协商建立会话密钥，而不是明文传输会话密钥。

### 5.2 数据传输

VPN 在数据阶段通常使用高效的对称加密，并通过认证标签、计数器等机制防止篡改、伪造、重放。

**VPN 加密通常终止于 VPN 服务器，不等于应用层的端到端加密**。若应用使用 HTTPS，TLS 仍可在客户端与目标网站之间提供端到端的传输保护。因此还需要考虑对 VPN 运营方的信任。

## 六、主流 VPN 协议

| 协议 | 技术基础 | 特点 |
|---|---|---|
| IPsec / IKEv2 | 网络层安全协议与密钥协商 | 企业 VPN、站点互联 |
| OpenVPN | TLS、TUN/TAP | 跨平台、配置灵活 |
| WireGuard | UDP、Noise、现代密码算法 | 协议简洁，性能表现较好 |
| L2TP/IPsec | L2TP 隧道 + IPsec 安全层 | 传统兼容性方案 |

### WireGuard：Cryptokey Routing

WireGuard 将 Peer 公钥身份与允许的隧道 IP 地址范围关联，例如：

```ini
[Peer]
PublicKey = ...
AllowedIPs = 10.8.0.2/32
```

这种映射既用于发送方向的 Peer 选择，也用于接收方向的源地址校验。

## 七、VPN 与代理的区别

| 对比 | VPN | HTTP / SOCKS 代理 |
|---|---|---|
| 主要层次 | L2 / L3 | 应用层 |
| 转发单位 | IP 包或以太网帧 | 应用请求或代理连接 |
| 接管机制 | 路由、虚拟网卡 | 应用代理配置、透明代理 |
| 是否必须解密业务 TLS | 否 | 通常否 |
| 典型场景 | 企业组网、远程接入 | 应用流量转发 |

部分现代代理软件也通过 TUN 接管系统流量，因此用户体验可能接近 VPN，但其内部仍可能是应用连接代理模型。

## 八、工程实现的关键问题

VPN 的关键技术关系：**路由控制 → 虚拟网卡 → 隧道封装 → 安全传输 → 解封装与转发**。

- **MTU / MSS**：额外隧道头增加包长，可能导致分片或 PMTU 黑洞。
- **TCP over TCP**：内外双层 TCP 的丢包恢复机制可能相互干扰。
- **NAT 穿透**：需要考虑 UDP 映射保持、地址变化和连接迁移。
- **加密吞吐量**：CPU、批处理、内核态实现、多核扩展都会影响性能。
- **路由 / DNS 泄漏**：流量接管不完整时可能绕过隧道。

**总结：VPN 不只是加密转发，而是借助虚拟网络设备、路由控制和隧道协议，在现有网络基础设施上构建一套逻辑网络，并利用密码学保护传输。**
