# Page Cache（页缓存）的底层原理

Page Cache 本质上是 Linux 内核利用物理内存缓存文件数据的一种机制。 它以页（Page）为基本管理单位，将磁盘文件的内容缓存在内存中，让后续文件读写尽可能通过内存完成，而不是每次都访问磁盘。

理解它，重点是四件事：缓存如何组织、读写如何工作、何时回写磁盘、内存不足时如何回收。

## 一、整体架构

用户进程

read / write / mmap

Linux 内核 Page Cache

文件偏移 → 内存页 → 脏页管理

文件系统 / 块设备层

文件偏移转换为磁盘块 I/O

SSD / HDD

假设一个文件大小为 12 KB，系统页大小为 4 KB，那么它对应的文件内容可以分成三个页：

### Page 0

偏移 0–4 KB

### Page 1

偏移 4–8 KB

### Page 2

偏移 8–12 KB

示例假设页大小为 4 KB；实际页大小取决于操作系统与体系结构配置。

内核以文件及文件偏移为依据，查找对应的缓存页。不同进程访问同一文件时，通常可以共享同一份 Page Cache 数据，不必各自再缓存一份文件内容。

## 二、读文件：缓存命中与缓存未命中

以 `read(fd, buf, len)` 为例。

进程调用 `read()`

内核查找对应文件偏移的缓存页

缓存命中

直接从 Page Cache 复制数据到用户缓冲区，通常无需磁盘读取。

缓存未命中

触发文件读取 I/O，将数据加载到 Page Cache，再向进程提供数据。

这里有一个关键细节：普通 `read()` 通常仍然需要把数据从内核 Page Cache 复制到用户态缓冲区。 所以缓存命中虽然避免了磁盘 I/O，但并不意味着完全没有数据复制。

另外，内核可能根据顺序读取模式进行预读，把后续文件页提前加载进缓存。

## 三、写文件：为什么写入不一定立即落盘？

对普通缓冲文件 I/O 而言，写操作通常会修改 Page Cache 中对应的内存页。

这些被修改、尚未完全同步到存储设备的页称为 Dirty Pages（脏页）。

进程调用 `write()`

修改 Page Cache

对应缓存页变为 Dirty

内核回写机制

根据脏页比例、时间及系统压力等条件调度写回

存储设备完成写入

因此，`write()` 成功通常只说明数据已被内核接受，并不必然代表数据已经持久化到物理介质。

如果需要更强的持久性保证，应用可以使用 `fsync()` 或 `fdatasync()` 等机制请求同步；最终保证仍取决于文件系统、存储设备和设备缓存的正确行为。

## 四、内核如何组织 Page Cache？

Page Cache 并不是一个简单的连续内存数组。现代 Linux 内核主要依托文件的 `address_space` 等结构管理文件缓存，并通过索引结构查找页面或 folio。

概念上可以理解为：

```
文件 inode / address_space
          |
          v
    文件偏移索引
          |
     +----+----+
     |         |
     v         v
   Page 0    Page 1
     |         |
     v         v
   内存页     内存页
```

需要区分两个概念：

- 文件偏移： 数据在文件中的逻辑位置。
- 内存页： 当前缓存文件内容的物理内存承载单位。

缓存页不要求在物理内存中连续；内核通过映射和索引将文件偏移与缓存页关联起来。现代内核还使用 folio 等抽象来支持多页粒度的缓存管理。

## 五、内存不足时如何回收？

Page Cache 会使用空闲内存，但不会无限占用内存。Linux 内存回收机制会根据内存压力判断哪些页面可以回收。

| 缓存状态        | 常见处理方式               |
| ----------- | -------------------- |
| 干净页（Clean）  | 通常可以直接丢弃，之后需要时再从磁盘读取 |
| 脏页（Dirty）   | 通常需要先写回，才能安全回收       |
| 正在使用或被固定的页面 | 不能简单地直接回收，需满足相应条件    |

这也是为什么 Linux 的内存使用情况不能简单地理解为“应用占用了多少内存”。文件缓存可以占用大量物理内存，但在系统需要内存时，其中一部分可以被回收。

## 六、回到 Kafka：为什么 Page Cache 很重要？

Kafka 将消息存储在普通日志文件中，因此能够直接受益于 Linux 的文件缓存机制。

- 写入： 顺序追加日志，利用 Page Cache 和批量回写减少对物理磁盘的同步等待。
- 读取： 热数据可能直接从内存读取，减少磁盘 I/O。
- 发送： 配合 `sendfile()` 等机制，在适用路径上减少用户态与内核态之间的数据复制。
- 内存管理： 由 Linux 统一管理文件缓存，Kafka 不必把全部日志消息保存在 JVM 堆中。

最终可以用一句话概括：

Page Cache 是操作系统建立在文件与存储设备之间的一层内存缓存；读操作利用它减少磁盘访问，写操作利用它延迟并合并磁盘写入，而内核通过脏页回写和内存回收机制管理其生命周期。
