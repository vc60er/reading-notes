# 一致性哈希的底层原理

## 1. 一致性哈希是什么

补充一下：

1. 是一种特殊的哈希数据接口：节点变动时候，尽可能的少迁移数据
2. 实现方式概括来说：
   1. 将 key 和节点都映射到一个哈希环上
   2. Key 对应的节点是，从环上该 key 的位置顺时针找到的第一个节点



一致性哈希（Consistent Hashing）本质上是：

> 把节点和数据都映射到同一个环形哈希空间，然后按顺时针找到负责节点。

核心价值：

> 当服务器节点增加或减少时，只需要迁移少量数据，而不是把几乎所有数据重新分片。



---

## 2. 普通 Hash 为什么有问题

假设有 3 台服务器：

```text
Node A
Node B
Node C
```

简单分片方式：

```text
server = hash(key) % N
```

例如：

```text
hash("user:1001") % 3 = 0 → A
hash("user:1002") % 3 = 1 → B
hash("user:1003") % 3 = 2 → C
```

增加一台机器后：

```text
server = hash(key) % 4
```

大量 Key 的结果会改变，因此大量数据需要迁移。

---

## 3. 一致性哈希的核心思想

建立一个固定的 Hash 空间，例如：

```text
0 ~ 2^32 - 1
```

然后把首尾连接起来形成 Hash Ring。

服务器本身也经过 Hash：

```text
hash(Node A) = 10
hash(Node B) = 30
hash(Node C) = 70
```

数据 Key 也经过 Hash：

```text
hash(key) = 某个环上的位置
```

规则：

> 数据沿顺时针方向寻找第一个服务器。

因此：

```text
Key → Hash → Hash Ring → 顺时针找节点 → Server
```

---

## 4. 为什么增加服务器只迁移少量数据

假设：

```text
A10
B30
C70
```

新增：

```text
D50
```

原来：

```text
B30 → C70
```

这一段数据属于 C。

加入 D 后：

```text
B30 → D50 → C70
```

因此只有原来属于 C、且位于 B30 到 D50 区间的数据改由 D 负责。

所以：

> 增加节点只影响新节点附近的一段区间。

删除节点同理：被删除节点负责的区间交给下一个节点。

---

## 5. 一致性 Hash 的本质

它本质上是在做：

> 把整个 Hash 空间切成很多区间，每个节点拥有其中一些区间。

例如：

```text
(70, 10] → A
(10, 30] → B
(30, 70] → C
```

节点变化时，只需要重新分配部分区间。

---

## 6. 数据倾斜问题

如果节点在 Hash Ring 上分布不均匀：

```text
A10
B11
C200
```

那么不同节点负责的数据量可能差异非常大。

这就是一致性 Hash 的经典问题：

> Hash 环上的节点分布不均匀。

---

## 7. 虚拟节点

解决办法是让一个物理节点对应多个虚拟节点：

```text
A → A1, A2, ..., A100
B → B1, B2, ..., B100
C → C1, C2, ..., C100
```

每个虚拟节点独立 Hash 到 Ring 上。

Key 找到的是虚拟节点：

```text
Key
 ↓
Virtual Node A2
 ↓
Physical Node A
```

虚拟节点越多，通常可以让数据分布更加均匀。

---

## 8. 一致性 Hash 的底层数据结构

工程实现中经常使用：

```text
TreeMap<Long, Node>
```

保存：

```text
Hash值 → 节点
```

例如：

```text
10 → A1
25 → C3
38 → B7
51 → A9
72 → C8
91 → B2
```

假设：

```text
hash(key) = 45
```

查找第一个：

```text
Hash >= 45
```

得到：

```text
51 → A9
```

如果没有找到，就回到 Hash Ring 开头。

因此查询通常是：

```text
O(log N)
```

# 普通 Hash 与一致性 Hash：节点变化时的迁移量

假设：

- 数据量为 M
- 原来有 N 个节点
- Hash 均匀分布

## 1. 普通 Hash：hash(key) % N

增加一个节点：

```text
N → N+1
```

原映射：

```text
H % N
```

新映射：

```text
H % (N+1)
```

一个 Key 不发生迁移，需要：

```text
H % N = H % (N+1)
```

因此：

```text
不迁移概率 ≈ 1/(N+1)
迁移概率 ≈ N/(N+1)
```

例如：

| 原节点数 | 增加后 | 迁移比例 |
|---:|---:|---:|
| 1 | 2 | 50% |
| 2 | 3 | 66.7% |
| 3 | 4 | 75% |
| 9 | 10 | 90% |
| 99 | 100 | 99% |
| 999 | 1000 | 99.9% |

---

# 为什么普通 Hash 的不迁移概率是 1/(N+1)

这里不能只枚举几个 H，因为 H 是 Hash 空间中的大量值。

假设 Hash 是均匀的有限整数空间，例如 64 bit：

```text
H ∈ {0, 1, ..., 2^64 - 1}
```

我们要求：

```text
H % N = H % (N+1)
```

设共同余数为 r：

```text
H % N = H % (N+1) = r
```

则：

```text
H = r + aN
H = r + b(N+1)
```

所以：

```text
aN = b(N+1)	
```

由于：

```text
gcd(N, N+1) = 1
```

所以：

```text
H = r + kN(N+1)
```

其中：

```text
r = 0, 1, ..., N-1
```

因此“不迁移”的 H 具有周期：

```text
N(N+1)
```

在每一个完整周期中：

```text
总共有 N(N+1) 个 H
其中 N 个 H 不迁移
```

因此：

```text
P(不迁移)
= N / [N(N+1)]
= 1/(N+1)
```

于是：

```text
P(迁移)
= 1 - 1/(N+1)
= N/(N+1)
```

---

## 一个重要的严谨性说明

严格来说，实际 Hash 空间通常是有限的，例如：

```text
0 ~ 2^64-1
```

而：

```text
N(N+1)
```

一般不一定整除 `2^64`。

因此严格概率存在极小的边界误差。

工程上通常写：

```text
P(不迁移) ≈ 1/(N+1)
P(迁移) ≈ N/(N+1)
```

这个结论的核心前提是：

> Hash 函数在 Hash 空间中近似均匀分布。

另外，不存在“在所有整数上均匀随机选择一个整数”的概率分布，所以严谨讨论应该基于实际有限 Hash 空间，或者基于周期/渐近意义来讨论。

---

# 一致性 Hash 的迁移量

在理想均匀分布条件下，原来 N 个节点，增加一个节点：

```text
N → N+1
```

新增节点平均获得约：

```text
1/(N+1)
```

的 Hash Ring 空间，因此平均迁移：

```text
M/(N+1)
```

也就是迁移比例约：

```text
1/(N+1)
```

与普通 Hash 对比：

```text
普通 Hash：
迁移比例 ≈ N/(N+1)

一致性 Hash：
平均迁移比例 ≈ 1/(N+1)
```

因此两者迁移量的理论比值约为：

```text
N
```

例如原来 100 个节点，增加第 101 个：

```text
普通 Hash：
≈ 99.01% 数据迁移

一致性 Hash：
≈ 0.99% 数据迁移
```

如果有 1 亿 Key：

```text
普通 Hash ≈ 9901 万 Key
一致性 Hash ≈ 99 万 Key
```

---

# 一个重要区别：Key 迁移量 ≠ 实际迁移成本

迁移 Key 的比例只是一个指标。

实际迁移成本还取决于：

```text
Key 数量
×
Value 大小
×
副本数量
×
网络传输
×
磁盘 IO
×
索引重建
```

因此：

> “一致性 Hash 平均迁移 1/N 数据”描述的是数据归属变化的规模，而不是所有系统资源开销都严格降低到 1/N。

---

# 最核心的公式

增加一个节点：

```text
普通 Hash：

迁移比例 ≈ N/(N+1)


一致性 Hash：

平均迁移比例 ≈ 1/(N+1)
```

所以：

```text
普通 Hash 的迁移量
────────────────── ≈ N
一致性 Hash 的迁移量
```

这就是一致性 Hash 在动态扩缩容场景中的核心价值。

---

# 进一步理解

整个思想可以浓缩为：

```text
普通 Hash：

节点变化
   ↓
Hash 取模规则整体变化
   ↓
大量 Key 映射变化


一致性 Hash：

节点变化
   ↓
Hash Ring 局部区间变化
   ↓
少量 Key 映射变化
```

也就是说，一致性 Hash 的核心并不只是“Hash Ring”，而是：

> **把节点变化造成的全局数据重分布问题，局部化成少数 Hash 区间的重新分配。**
