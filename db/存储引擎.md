# 存储引擎



## B+ 树

B+ 树是为**外部存储**场景设计的**平衡查找树**。它的核心思想是：让一个节点容纳大量索引项，从而降低树高；同时把数据记录组织在叶子层，便于顺序遍历。

B+ 树以页(16KB)来做组织节点，即一个节点大小是16KB



### 核心特征：

1. 多路分支：一个节点有多个子节点
2. 有序索引：节点内部的键按照顺序组织，用于确定查找方向。
3. 叶子层等深：所有叶子节点位于同一层，树始终保持平衡。
4. 数据集中在叶子层：内部节点主要承担路由作用，叶子节点存放索引记录。
5. 叶子节点有序相连：范围查询找到起点后，可以顺着链表继续扫描。



### 内部节点

作用：用于索引导航，仅存储索引值和指针

内部包括：

- N 个分割键：分割键就是索引的值，索引
- N+1 个指针：
  - 最左侧的指针，指向小于最左侧 K 的数据范围
  - 最右侧的指针，指向大于等于最右侧 K 的数据范围
  - 中间的指针，指向的数据范围是它左右两侧键的访问（左闭右开区间）

### 叶子节点

作用：存储数据，按照索引的顺序，存储完整的数据行

例如

```
叶子页：
┌────────────────────────────────────┐
│ id=1, name=Alice, age=25           │
│ id=2, name=Bob,   age=30           │
│ id=3, name=Carol, age=28           │
└────────────────────────────────────┘
```

### 数据查找

- 查询过程

  1. 在根节点，执行二分查找，找到内部节点的指针，跳到内部节点

  1. 在内部点，执行二分查找，找到叶子节点的指针，跳到叶子节点

  1. 在叶子节点，执行二分查找，找到数据

- 时间复杂度：

​	\[ O(\log N) \]

### 节点分裂

> B+ 树必须支持动态插入，同时保持有序和平衡。
>
> 插入数据时，如果空间不足，需要将其分裂为两部分才能放入新数据

插入的过程：

1. 从根节点开始查找目标叶子页。
2. 在叶子页中找到正确位置。
3. 如果有足够空间，直接插入。
4. 如果页面放不下，执行页分裂。

分裂的过程：

1.　分配一个新节点。
2.　将一半元素从分裂节点复制到新节点。
3.　将新元素放入相应节点。
4.　在分裂节点的父节点处，添加一个分隔键和指向新节点的指针。
5.　如果父节点也溢出，分裂继续向上递归。
6.　如果根节点分裂，则创建新根节点，树高增加一层。



这里有一个重要特性：**B+ 树通常在根节点处增长高度，而不是让某一个叶子分支单独长高。**

因此，所有叶子始终保持在同一层，树的平衡性质不会被破坏。

### 节点合并

> 删除数据后，节点内无数据，

合并过程：

1.　从右节点复制所有元素到左节点。
1.　从父节点删除右节点指针（如果是非叶子节点合并，则将此指针进行降级）
1.　删除右节点。



### 层高

- 内部节点的扇出

假设，一个内部节点可用于索引和指针的空间是 14 KB，一组索引+指针占 16B。

那么，一个内部节点可扇出子节点：14*1024/16=896

- 容量和层高的关系如下：

\[ N\approx F^{H-1}\times L \]

> \(N\)：容量，索引记录数量。
>
> \(F\)：平均扇出，即一个内部节点平均指向多少个子节点。
>
> \(H\)：树的层数。
>
> \(L\)：每个叶子页平均容纳的记录数

假设：

- 内部节点平均扇出为 500；
- 每个叶子页平均存储 300 条记录。
- 层高 3

那么

容量为：\[ 500^2\times300=75,000,000 \]

即，约 7500 万条记录。

四层树理论上可覆盖的规模则进一步扩大约 500 倍。



### 读取速度优势总结

- B+ 树索引：多路树结构，扇出高、树高低，通常只需访问少量索引页即可定位记录。

- 页式存储：一次读取一个数据页（默认通常为 16KB），同时获取多条相邻记录，摊薄 I/O 成本

- Buffer Pool：缓存数据页和索引页，命中时直接从内存读取，避免磁盘 I/O。

- 有序叶子节点：范围查询定位起点后，可以沿叶子页顺序扫描，减少重复查找

- 局部性与预读：利用相邻数据访问的局部性，在合适的场景下提前加载后续数据页。









## B 树

### 核心特征：

1. 多路分支：一个节点可以有多个子节点，而不是像二叉树那样最多两个。
2. 节点内有序：节点中的键值按照大小排序。
3. 平衡：所有叶子节点处于同一深度。
4. **数据可存于内部节点：查找时可能在到达叶子节点之前就找到目标数据。**



### 与 B+ 树的相同点

1. 多路查找树：一个节点可以存储多个有序键值，并拥有多个子节点。
2. 有序性：节点内的键值有序，子指针根据键值范围划分搜索空间。
3. 平衡性：所有叶子节点处于同一深度，避免树退化为链表。
4. 查找效率高：查找、插入、删除的时间复杂度通常为 \(O(\log N)\)。
5. 支持动态调整：插入和删除可能触发节点分裂、借位或合并，以维持树的平衡。

### 与 B+ 树的不相同点

| 对比维度     | B 树                                     | B+ 树                                          |
| ------------ | ---------------------------------------- | ---------------------------------------------- |
| 数据存储位置 | 内部节点和叶子节点均可存储实际记录       | 内部节点通常只存分隔键和子指针；叶子存索引记录 |
| 查找方式     | 可能在内部节点命中                       | 通常需要到达叶子层                             |
| 内部节点扇出 | 由于可能存储较大的记录，扇出可能较低     | 内部节点较紧凑，通常扇出更高                   |
| 范围查询     | 通常需要中序遍历或利用额外的链接结构     | 叶子节点通常按序链接，范围扫描更方便           |
| 顺序遍历     | 通常不如 B+ 树方便                       | 更适合范围查询与顺序扫描                       |
| 典型用途     | 文件系统、内存数据结构等场景中可见其变体 | 关系数据库索引中广泛使用                       |



### 与 B+ 树的优势

主键能命中的时候，可能查找速度更快。理由是：B 树的内部节点中的键值本身就可能是查找结果，不一定需要继续向下访问
